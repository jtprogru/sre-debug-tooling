# Медленный диск

> **TL;DR:** `iostat -x 2 5` на ноде. `%util` под сотню и высокий `await` — устройство насыщено. `%util` низкий, а приложение всё равно тормозит — диск ни при чём.

## Когда применять

Латентность на запись в приложении, база жалуется на медленные запросы без изменения плана, флаш логов копится, PVC работает медленнее, чем неделю назад.

## Быстрая диагностика

Внутри пода, по смонтированному тому:

```bash
df -h /data
ioping -c 20 /data
```

На ноде, где живут настоящие цифры:

```bash
./hack/kdebug.sh node <node>
```

```bash
iostat -x 2 5
pidstat -d 2 5
```

## Что означают ответы

`%util` под 100 и `await` в десятках миллисекунд — устройство насыщено. `pidstat -d` назовёт процесс, который это делает, и часто это не то приложение, из-за которого тебя подняли.

`%util` низкий, `await` низкий, приложение тормозит — со стораджем всё нормально. Смотри на паттерн fsync: база, коммитящая каждую транзакцию на сетевой том, упирается в латентность, а не в пропускную способность, и `iostat` при этом выглядит скучающим.

`r_await` заметно выше `w_await` — read amplification, обычно кеш перестал влезать в память.

Цифры выглядят прилично, но облачный том зажат лимитом — сверь provisioned IOPS с тем, что ты просишь. Кончившиеся burst-кредиты выглядят ровно как внезапно замедлившийся диск, потому что это он и есть.

## Как померить нормально

`fio` даёт число, которое можно с чем-то сравнить. Гоняй по файлу на томе, никогда по сырому устройству:

```bash
fio --name=lat --filename=/data/fio-test --size=512M --bs=4k --rw=randread \
    --ioengine=libaio --iodepth=16 --direct=1 --runtime=30 --time_based --group_reporting
rm -f /data/fio-test
```

Это съедает реальный IO на томе, который и так подозревают в медлительности. На проде во время инцидента такое запускают осознанно, а не диагностическим рефлексом.

## Митигация

Сначала убери шумного соседа, потом ресайзи — `pidstat -d` уже сказал, кто это. Если том зажат лимитом, расширение обычно поднимает и потолок IOPS, и это быстрее миграции. Если забился том с логами, `ncdu /data` найдёт директорию быстрее, чем `du`.

## Root cause

Сайдкар, пишущий debug-логи на тот же том. Бэкап, наложившийся на пик трафика. Кончившиеся burst-кредиты на облачном томе, размер которого считали по среднему, а среднее уехало. База, у которой working set перерос page cache.
